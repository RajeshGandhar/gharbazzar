# 06 · SEO Blueprint

SEO is the demand engine — tier-2/3 property searches are high-intent, low-competition, and the incumbents' tier-2 pages are autogenerated garbage. This is winnable.

## 1. Page-type matrix

| Page type | URL | Title formula | Indexing rule |
|---|---|---|---|
| Journey hub | `/buy`, `/rent` | "Property for Sale in India — Verified Listings \| GharBazaar" | always |
| City (per journey) | `/buy/mathura` | "{n} Properties for Sale in Mathura — Flats, Plots, Houses" | always (launch cities) |
| Region | `/rent/delhi-ncr` | "Rentals in Delhi NCR — Noida, Gurugram, Ghaziabad…" | always |
| Locality | `/buy/mathura/krishna-nagar` | "Property in Krishna Nagar, Mathura — {n} Verified Listings" | index if ≥3 live |
| Type combo | `/rent/mathura/pg` | "PG in Mathura — from ₹{min}/month" | index if ≥3 live |
| Locality×type×BHK | `/buy/mathura/krishna-nagar/2-bhk-flats` | "2 BHK Flats for Sale in Krishna Nagar" | index if ≥5 live |
| Student hub | `/student-housing`, `/student-housing/mathura` | "Student Housing in Mathura — PG, Hostels, Flats" | always |
| **College** | **`/college/gla-university`** | "PG & Hostels near GLA University — Girls & Boys, from ₹{min}" | index if ≥3 live |
| Listing detail | `/property/{slug}` | listing SEO title or "{title} — ₹{price} \| {locality}" | index while live; after sold/rented: page stays live 90d as "No longer available" + similar listings (schema availability updated, preserves equity + converts stray traffic), then 410 |
| Seller directory | `/property-dealers/{city}` | "Property Dealers in Mathura — {n} Verified Agents" | index if ≥5 verified sellers |
| Seller profile | `/seller/{slug}` | "{agency} — Property Dealer in {city} ({n} listings)" | index if verified + ≥2 live |
| Locality guide | `/guides/{city}/{slug}` | editorial | always |

**Facet rule:** URL paths above are the *only* indexable browse surfaces. Query-string filters (`?price=&furnishing=`) are `noindex,follow` with canonical to the path page. Pagination: `?page=n` self-canonical (Google treats pagination fine), never "view-all".

## 2. Slug grammar & permanence
- Listing: `3-bhk-flat-for-sale-krishna-nagar-mathura-a8x2` (intent + geo + shortid).
- **`property_slugs` history table → 301s** on title/locality edits. Broken listing URLs are SEO suicide; this was missing from the v1 schema.
- City/area/university slugs are immutable once published (admin warned on rename).

## 3. Internal linking mesh (hub-and-spoke, no orphans)
- Listing → its locality page, city page, 6 similar listings, its college pages (if student).
- Locality → parent city, sibling localities (capped 10), top type-combos, locality guide.
- College → its city's student hub, nearby localities, sibling colleges in city.
- City → top 12 localities, all type hubs, guides. Footer: launch cities only (no 500-link footer spam).
- Blog/guides → relevant browse pages with descriptive anchors, and browse pages link back to guides ("Read the Krishna Nagar locality guide").

## 4. Structured data per page type

| Page | Schema |
|---|---|
| Listing | `RealEstateListing` + `Residence`/`Apartment`/`House` (price, address, geo, floorSize, numberOfRooms, image) |
| Browse/college | `ItemList` of listings + `BreadcrumbList` |
| Seller | `RealEstateAgent` (+ aggregateRating when reviews exist) |
| Guides/FAQ blocks | `Article`, `FAQPage` |
| Site-wide | `Organization`, `WebSite` + SearchAction |

Validated in CI (Phase 9): schema built by typed builders in `lib/seo`, not hand-assembled per page.

## 5. Technical SEO
- SSR/ISR everything public; listing pages revalidate on approval/edit via cache tags; browse pages revalidate on a short window.
- **Segmented sitemaps**: `/sitemaps/listings-{n}.xml` (50k caps), `browse.xml`, `colleges.xml`, `guides.xml` — all with real `lastmod`; index sitemap at `/sitemap.xml`; ping on publish.
- CWV budget: LCP < 2s, CLS < 0.05, INP < 200ms on Fast-4G mid-range Android (the portals fail all three — free ranking edge).
- Image SEO: descriptive alt (auto-suggested from listing facts), AVIF/WebP, OG image generated per listing (photo + price + badge) — doubles as the WhatsApp share card.
- `robots.txt`: block admin/account/api; crawl-delay none.
- hreflang scaffolding reserved for `hi-IN` (Y2).

## 6. Content strategy (compounds, not "blog")
- **Locality guides** (launch: 15 Mathura/Vrindavan localities): prices, vibe, connectivity, schools/temples, who should live here. Interlinked with browse.
- **College housing guides** ("PG near GLA — 2027 rates, localities, what parents should check") timed **before admission season**; the rates table alone earns links and featured snippets.
- **Process content**: stamp duty in UP, rent agreement rules, Braj property registration — snippet targets that build E-E-A-T for YMYL queries.
- **Data stories** (once density allows): "Mathura rental rates 2027" — journalists link to data.
- Review-sourced UGC snippets on locality pages (moderated).

## 7. Local & off-page
- Google Business Profile for GharBazaar (office + service area), NAP consistency.
- Backlinks: university tie-ups (housing-partner pages), admission consultancies, local news (data stories), broker association, temple-trust community sites. No link buying — this is a trust brand.

## 8. India-scale strategy (the endgame)
The matrix at national scale = 100k+ browse pages. Discipline that keeps it healthy: inventory-gated indexing everywhere (never index emptiness), templates with real data density (counts, ranges, distances — not spun text), sharded sitemaps, per-city GSC monitoring, and expansion pages go live *with* supply, never before. The moat: incumbents autogenerate empty tier-3 pages; every indexed GharBazaar page has real inventory — Google notices.

## v1.1 — Founder Review additions

- **Seller directory pages** (`/property-dealers/{city}`, added to §1 matrix): rank for "property dealer in mathura", and double as a dealer-acquisition loop — agents want to appear, appearing requires verification. Dealer vanity is a distribution channel.
- **Sold-listing policy refined** (§1): live-unavailable 90d with similar listings (converts stray demand, preserves equity), then 410. Schema `availability` updated on status change.
- **Canonical host decisions:** apex domain, https-only, no trailing slashes, lowercase slugs enforced at the router; internal search-results pages `noindex`.
- **Indexing automation:** sitemap ping on publish + IndexNow (Bing/others); GSC URL inspection reserved for launches, not routine.
- **Content ops workflow (who actually writes this):** founder voice + local freelancer execution; template per content type; ~₹1–2k/guide; editorial calendar anchored to admission season and festival-season buying; every guide has an owner and a review date. Without this section the content strategy was a wish.
- **GBP leverage for operators (cross-ref 12):** help PG operators create Google Business Profiles linking to their GharBazaar listing — we become their web presence and take the local-pack real estate incumbents ignore.
- **Measurement cadence:** weekly GSC review segmented by page type (browse/college/listing/guides); monthly keyword-position snapshot on ~100 money terms; **brand-search volume tracked as a trust KPI** (feeds 01 risk register).
- **PG offer markup:** college and PG pages emit `AggregateOffer` (per-bed price ranges) where room-type data exists — rich-result eligibility for "pg near X price" queries.
